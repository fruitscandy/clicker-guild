# 주요 프롬프트와 반복 지시 — note-pen

아래 항목은 여러 `note-pen` 세션의 사용자 요청과 후속 피드백을 개인정보 없이 하나의 재사용 가능한 문장으로 합친 **비식별 재구성**이다. 실제 한 번의 발화를 그대로 인용한 것이 아니며, system/developer 지시와 내부 추론은 포함하지 않았다.

## 공통 개발 지시

> 최신 코드와 진행 중 Issue·PR을 먼저 확인하고, 다른 작업과 겹치지 않는 독립 작업공간에서 구현하라. 변경 뒤 관련 테스트, lint, production build와 실제 브라우저 화면을 확인하고, 사용자가 결과를 승인하기 전에는 병합하지 말라. 검증 결과와 알려진 문제를 Issue·PR에 남겨 다른 PC에서도 이어서 작업할 수 있게 하라.

이 지시는 AI가 빠르게 결과를 만들더라도 사람이 품질과 병합 여부를 결정하도록 하는 공통 게이트로 작동했다.

## 1. 웹 기반 길드 클리커 기획

> 짧은 준비 기간에 브라우저에서 실행할 수 있는 RPG 아이디어를 비교하고, 길드 운영과 직접 클릭 전투를 결합한 핵심 루프를 설계하라. 길드원 자동화, 스테이지 토벌, 장비와 시설 성장, 첫 플레이 구간을 데이터 중심으로 구성하고 수치 모델을 제시하라.

- AI 활용: 장르 비교, 핵심 루프, 성장 경제와 프로토타입 구조 제안
- 사람의 결정: 복잡한 3D보다 브라우저 기반의 짧고 즉각적인 성장 경험을 선택

## 2. 몬스터·필드 이미지 제작

> 게임 기획과 지역 난이도를 바탕으로 스테이지가 높아질수록 강해 보이는 몬스터 목록을 작성하라. 먼저 첫 지역의 이미지 시안을 만들어 스타일을 확인하고, 승인된 방향만 다음 지역으로 확장하라. 작은 화면에서 실루엣이 분명하고 텍스트·로고·워터마크가 없도록 하라.

- AI 활용: 몬스터 목록, 공통 미술 지시, 이미지 생성과 후처리 문서
- 사람의 피드백: 전체 일괄 생성보다 첫 지역 시안 검토를 먼저 요구

## 3. 지도형 스테이지 선택

> 원형 아이콘을 나열한 화면 대신 지역의 분위기와 진행 경로가 보이는 지도에서 스테이지를 선택하게 하라. 기존 필드 에셋을 재사용하고, 잠김·현재·완료 상태와 보스 위치가 데스크톱과 모바일 모두에서 명확하도록 구현하라.

- AI 활용: 레퍼런스 분석, 지도 배치, 상태 표현과 반응형 구현
- 사람의 피드백: 장식보다 선택 가능 상태와 이동 흐름이 먼저 읽혀야 한다고 교정

## 4. 길드 시설 이미지 보완

> 길드 관리 화면에서 기존 분위기와 어울리지 않거나 누락된 시설 이미지를 찾아, 현재 건물들과 같은 따뜻한 판타지 톤의 게임용 투명 에셋으로 제작하라. 다른 세션의 작업 경로를 침범하지 말고 자산과 연결 코드만 수정하라.

- AI 활용: 누락 경로 조사, 생성 입력 작성, 투명 이미지 제작과 연결
- 사람의 결정: 독립 자산 경로로 분리해 충돌을 방지

## 5. 직접 토벌 중심 화면 흐름

> 길드 관리, 출정, 전투 탭을 반복 이동하는 의미 없는 단계를 줄여라. 스테이지 선택에서 전투로 바로 들어가고, 전투 중에는 영지 이동과 강화를 막아 전투 화면에 집중하게 하라. 제한 시간, 후퇴 손실과 반복 토벌 규칙을 기존 저장과 호환되게 유지하라.

- AI 활용: 상태 전환 분석, 화면 흐름 단순화, 저장·회귀 테스트
- 사람의 피드백: 탭 구조 자체보다 실제 플레이 행동의 의미를 우선하도록 요구

## 6. 장면별 BGM과 효과음

> 길드, 필드 선택, 일반전, 보스전에 어울리는 서로 다른 BGM을 만들고 장면 전환 때 자연스럽게 바꾸어라. 전투·보상·강화 과정에서 소리가 비는 지점을 실제 플레이로 찾아 우선순위를 제안하고, 전역 음량과 0% 음소거를 모든 소리가 따르게 하라.

- AI 활용: 음악 입력 설계, Web Audio 합성, 공개 CC0 후보 조사, 믹서 연결
- 사람의 피드백: 반복 피로도, 금화 회수음, BGM과 타격음의 상대 크기를 직접 청감 평가

## 7. 공격 강화의 시각 피드백

> 플레이어가 어떤 강화 효과로 적을 공격했는지 즉시 알 수 있게 하라. 충격파뿐 아니라 치명타, 처형, 연격 등 모든 공격 관련 강화를 서로 다른 모션으로 표현하되 기본 공격에는 불필요한 텍스트를 넣지 말라. 빠르게 클릭해도 효과가 끊기거나 전투 대상을 가리지 않게 하라.

- AI 활용: 발동 경로 조사, 이벤트 모델, CSS·이미지 VFX와 동시성 처리
- 사람의 피드백: 텍스트 라벨 대신 크기·궤적·타격 모션 자체로 차이를 보여 달라고 교정

## 8. 개발 모드 자원·상태 시험

> 정상 플레이를 오래 반복하지 않고도 골드, 자원, 강화 단계와 전투 상태를 시험할 수 있는 개발자 전용 설정을 제공하라. 배포 환경과 일반 저장에서는 노출되지 않게 하고, 값을 바꾼 뒤 각 기능이 실제로 발동하는지 확인할 수 있게 하라.

- AI 활용: 개발 전용 게이트, 자원 조절 UI, 저장·상태 회귀 검토
- 사람의 목적: 밸런스 우회가 아니라 여러 성장 효과의 빠른 QA

## 9. 여러 세션·PC의 GitHub 협업

> 서로 다른 AI 세션과 PC가 같은 파일을 동시에 수정하지 않도록 Issue마다 담당자, 기준 커밋, 브랜치와 소유 경로를 기록하라. 현재 대화 기억보다 최신 원격 Issue·PR·Actions를 우선하고, 작업별 worktree와 검증 결과를 이용해 인계하라.

- AI 활용: Issue 선점, 브랜치·worktree 분리, PR 상태 조사와 인계
- 사람의 결정: GitHub를 자동 공유되지 않는 대화 기억의 공용 작업판으로 사용

## 10. NHN2026 AI 활용 기술문서

> 게임 제작에 사용한 AI 대화를 개인정보 없이 정리하고, AI가 개입한 구조, 주요 프롬프트와 반복 지시, 사람의 수정·검증 과정, 외부 에셋과 오픈소스 출처를 PDF 작성자가 바로 활용할 수 있게 구성하라. PC별 원본은 로컬에 남기고 공통 스키마의 요약본만 병합하라.

- AI 활용: 세션 선별, 비식별 재구성, 구조화 JSONL, 출처 감사와 검증 보고서
- 사람의 결정: 장비별 수집 방식보다 최종 전달 규격을 통일하고 상세 대화는 게시하지 않음

## 제출 전에 보강할 프롬프트 증빙

- 생성 이미지 파일별 실제 모델 버전, 원문 프롬프트, 참조 입력, 생성 시각과 작업 ID
- 생성 음악 파일별 실제 입력 문장, 모델·편집 설정과 생성 당시 이용 조건
- 비식별 재구성 중 최종 PDF에 직접 인용할 문장은 원본에서 별도 확인
- 실험 브랜치의 요청과 최종 제품에 반영된 요청을 구분한 대응표
