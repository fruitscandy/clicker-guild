# note-pen AI 활용 요약

`note-pen` 자료에서 확인되는 AI의 역할은 게임 런타임의 플레이 제어가 아니라 **개발 단계의 기획, 조사, 에셋 제작, 코드 구현, 검증, 저장소 협업**이다. AI가 제안하거나 만든 결과는 사람이 화면·소리·플레이 흐름을 확인하고 반복 수정한 뒤 정적 파일과 결정론적 웹게임 코드로 확정됐다.

## 개발 흐름

1. 사람이 목표 플레이 경험과 수정 기준을 제시했다.
2. AI가 최신 코드, Issue·PR, 진행 중 작업과 충돌 경로를 조사했다.
3. 독립 작업공간에서 코드·이미지·오디오 후보를 만들었다.
4. 자동 테스트, lint, production build와 실제 브라우저 확인을 수행했다.
5. 사람이 시각·청각 결과를 평가하고 추가 요구를 제시했다.
6. 승인된 작업만 PR로 통합하고 GitHub에 검증·인계를 남겼다.

## 대표 활용 사례

### 게임 기획과 수치 모델

초기에는 웹에서 빠르게 실행할 수 있는 RPG·클리커 아이디어, 유사 장르, 성장 곡선과 경제 모델을 조사했다. 사람은 길드 운영, 직접 공격, 길드원 자동화, 스테이지 토벌을 결합하는 방향을 선택했고 AI는 첫 플레이 구간과 수치 구조를 반복 계산 가능한 형태로 정리했다.

### 이미지·UI 제작

몬스터, 필드, 길드 시설, 지도, 전투 강화 효과의 시각 방향을 자연어로 정의하고 이미지 생성 또는 코드 기반 표현으로 옮겼다. 생성된 이미지는 곧바로 채택하지 않고 투명 배경, 실루엣, 작은 화면 가독성, 게임 화면에서의 크기와 배치를 확인했다. 단조로운 목록형 스테이지 선택은 지역 지도를 이용한 선택 화면으로 개선했고, 길드 시설과 공격 강화 효과는 기존 자산과 구분되는 시각 언어를 갖도록 반복 수정했다.

### 오디오 제작과 검증

길드, 필드 선택, 일반전, 보스전의 BGM 구조와 전투·보상·강화 효과음을 조사했다. 일부 소리는 Web Audio로 합성하고 일부는 출처가 확인된 CC0 음원을 사용했다. 사람이 실제 플레이에서 BGM과 효과음의 상대 음량, 금화 회수음 누락, 반복 피로도를 평가했고 AI가 신호 경로와 전역 음량 설정을 점검했다.

### 구현·QA·개발 도구

탭 이동 중심 흐름을 직접 토벌 진입 구조로 단순화하고, 전투 중 이동 제한과 후퇴 패널티 등 핵심 규칙을 코드에 반영했다. 성장 효과를 빠르게 확인할 수 있도록 개발 모드 자원 조절과 테스트 경로를 제안했으며, 자동 테스트와 브라우저 플레이 확인을 함께 사용했다.

### 여러 AI 세션의 협업

여러 PC와 세션의 대화 기억은 자동 공유되지 않으므로 GitHub Issue, PR, Actions와 저장소 문서를 공용 기억으로 사용했다. AI는 작업별 브랜치·worktree, 수정 경로 선점, 검증 결과, 병합 승인 상태를 기록했고, 충돌 가능성이 있는 공용 파일은 순서를 정해 통합했다.

## 사람의 핵심 판단

- 어떤 게임 아이디어와 기술 스택을 채택할지 결정했다.
- 게임 화면에서 이미지가 자연스럽고 읽기 쉬운지 판정했다.
- 효과음과 BGM이 실제 플레이에서 적절한지 청감 평가했다.
- 단순 텍스트 대신 모션과 타격감으로 성장 효과를 표현하도록 교정했다.
- 개인정보와 출처가 불완전한 자료는 제출 근거에서 제외하거나 보완 항목으로 남겼다.
- 최종 병합 여부와 공개 범위를 결정했다.

## 제출 문서 작성 시 한계

이 자료는 개인정보 보호를 위해 원문을 재서술한 요약이며 정확한 인용문 증빙이 아니다. 이미지 생성물의 파일별 모델·프롬프트·작업 ID, 생성 당시 서비스 약관, 일부 런타임 이미지의 출처, 실제 제출 빌드의 production SBOM은 아직 완결되지 않았다. 최종 PDF에서는 확인된 내용과 미확인 내용을 구분하고 `external-sources.md`의 보완 목록을 유지해야 한다.
