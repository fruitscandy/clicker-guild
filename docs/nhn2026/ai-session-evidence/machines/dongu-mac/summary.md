# dongu-mac Clicker Guild AI 활용 내역 요약

## 한눈에 보는 범위

2026년 8월 8일부터 10일까지 이 macOS 장비에서 진행된 Clicker Guild 관련 기록을 9개 논리 세션으로 묶었다. 실질 사용자 요청은 151개였고, assistant가 사용자에게 보여 준 진행·결과 메시지는 795개였다. 대화 원문, 하위 에이전트 기록, 도구 출력, 첨부 파일과 로컬 식별 정보는 싣지 않았다.

AI는 초기 게임 기획 정리, 저장소 구조 분석, 이미지·애니메이션·효과음 제작, React 게임 구현, 밸런스 조정, 브라우저 QA, 자동 테스트, GitHub 협업까지 개발 전 과정에 쓰였다. 사용자는 게임의 핵심 재미, 아트 품질, 스토리의 직관성, 오디오 체감, 플레이 시간과 병합 여부를 직접 판단하고 반복적으로 수정 방향을 제시했다.

## AI 활용의 핵심 특징

### 1. 텍스트에서 플레이 가능한 시스템까지 연결

초기 한 번의 기획 입력을 AI가 전투, 길드원, 고용, 영지 성장, 장비, 재화, 보스와 MVP 범위로 나눴다. 이후 같은 요구를 코드와 데이터 구조에 연결해 30개 전투 스테이지, 15단계 무기, 길드원 25명, 10개 필드, 업그레이드와 튜토리얼 같은 실제 기능으로 발전시켰다.

### 2. 생성형 이미지와 후처리 파이프라인

몬스터, 필드, 길드 성장, 시설, 재화, 길드원 애니메이션과 스킬 VFX에 이미지 생성을 활용했다. AI는 저장소의 기존 캐릭터·필드 톤을 분석해 프롬프트를 만들고, 생성 결과를 크로마키 제거, 알파 가장자리 정리, WebP 변환, 크기 정규화, manifest 매핑과 브라우저 검증까지 연결했다. 사용자가 “홍보물 같다”, “평면적이다”, “사진이 잠깐 뜨는 것 같다”고 평가한 결과는 실제 게임용 스프라이트와 짧은 모션 합성으로 다시 제작됐다.

### 3. 코드·오디오·시각 QA의 반복

AI는 Next.js/React 코드를 수정한 뒤 lint, production build, 렌더링·전투·오디오 회귀 테스트를 실행했다. 화면 작업은 데스크톱과 모바일에서 직접 열어 위치, 클릭 차단, 오버플로, 이미지 로드, 콘솔 오류를 점검했다. 오디오는 합성음으로 시작해 사용자의 청감 피드백에 따라 CC0 실녹음과 런타임 믹싱을 도입했다.

### 4. 사람이 방향과 품질을 결정

사용자는 핵앤슬래시의 속도감, 10~20분 플레이 시간, 세계가 지워지는 단순한 오프닝, 몬스터를 가리지 않는 튜토리얼, 작은 VFX, 금속성 동전음처럼 자동 테스트로 판정하기 어려운 기준을 정했다. AI는 처음 해석을 고집하지 않고 요구를 다시 분해해 코드·아트·음향을 반복 수정했으며, 병합은 사용자의 명시적 승인 뒤 수행했다.

## NHN2026 기술문서용 서술 초안

Clicker Guild에서는 Codex를 개발 단계의 분석·창작·구현·검증 도구로 사용했다. 게임 실행 중 AI 모델이 플레이를 제어하는 구조는 아니며, AI가 만든 코드와 에셋은 사람이 확인하고 테스트한 뒤 정적 파일과 결정론적 브라우저 로직으로 확정됐다.

개발은 “사람의 목표와 체감 기준 제시 → AI의 코드·자산 영향 분석 → 격리된 구현 → 자동 테스트와 브라우저 확인 → 사람의 수정 피드백 → PR 병합” 순환으로 진행됐다. 이미지 생성은 단순 시안 제작에서 끝나지 않고 투명화, 크기·형식 최적화, 런타임 매핑, 모바일 가독성 검증까지 포함했다. 오디오는 Web Audio 합성과 공개 CC0 실녹음을 혼합했으며, 출처 파일을 저장소에 남겼다.

가장 중요한 성과는 여러 종류의 AI 보조 작업을 하나의 플레이 경험으로 통합한 점이다. 초기 기획, 길드 성장, 몬스터·필드·무기·스킬 에셋, 전리품 경제, 오프닝과 튜토리얼이 각각 독립 작업으로 제작됐지만 Issue·PR·테스트를 공용 기억으로 사용해 충돌을 줄였다. 사용자는 모든 시각·청각 결과를 직접 평가했고, 특히 과도한 스토리 설정, 큰 VFX, 부자연스러운 합성음, 느린 초반 진행을 반복 교정했다.

## 제한사항

이 자료는 원문 증빙이 아니라 개인정보를 제거한 의미 요약이다. 세션 안에서 생성형 이미지 사용은 다수 확인되지만, 모든 파일을 정확한 모델 버전·프롬프트·참조 입력·생성 작업 ID와 연결하는 대장은 없다. 외부 에셋 출처와 OSS 라이선스도 저장소의 부분 기록을 바탕으로 한 중간 감사이므로, 최종 PDF 전 실제 제출 빌드와 `external-sources.md`의 보완 목록을 다시 대조해야 한다.
