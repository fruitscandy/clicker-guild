# 주요 프롬프트와 지시 사항 카탈로그

이 문서는 NHN2026 「AI 대상 주요 프롬프트 및 지시 사항」 항목에 활용할 수 있도록 `desk64`의 Clicker Guild 세션을 비식별 재구성한 것이다. 시스템·개발자 지시, 내부 추론, 도구 호출 메타데이터는 포함하지 않았다.

## 읽는 방법

- **정확 문구**: 사용자에게 표시된 대화에서 개인정보가 없는 프롬프트 문장을 그대로 보존한 항목이다.
- **비식별 재구성**: 여러 차례의 사용자 요구·후속 피드백을 하나의 재사용 가능한 프롬프트로 새로 쓴 항목이다. 실제 한 번의 발화를 그대로 인용한 것이 아니다.
- 결과와 인간 피드백을 함께 적어, AI 출력이 자동 채택된 것이 아니라 검토·수정됐음을 보인다.
- 아래 번호는 논리 세션 ID와 일대일 대응하지 않는다. 한 세션의 여러 반복을 주제별로 합쳤다.

## 공통 개발 지시

여러 구현 세션에서 다음 조건이 반복됐다.

> 기존 코드와 진행 중 작업의 충돌 범위를 먼저 확인하고, 독립 작업공간과 작업별 브랜치에서 구현한다. 변경 뒤 자동 테스트와 production build를 실행하고 전용 로컬 미리보기를 제공한다. 사용자가 화면 또는 소리를 확인해 명시적으로 승인하기 전에는 병합하지 않는다. 병합 뒤에는 미리보기 서버와 임시 프로세스를 종료한다.

이 지시는 저장소의 협업 규칙으로도 문서화됐으며, AI가 빠르게 구현하더라도 사람의 승인과 재현 가능한 검증을 병합 게이트로 유지하는 역할을 했다.

## 1. 길드 운영 게임의 핵심 구조

**표현 수준:** 비식별 재구성

> 플레이어가 판타지 길드 운영자가 되어 NPC 모험가에게 전투·비전투 의뢰를 맡기는 게임을 설계하라. 배정, 정보 조사, 장비 지원, 성공률, 수수료, 전리품 거래, 실패 후속 사건, 길드 성장과 복수 엔딩을 연결하고, 단계별로 테스트 가능한 웹 프로토타입을 구현하라. 시뮬레이션 규칙과 UI를 분리하고 데이터 중심으로 구성하라.

- AI 활용: 일일 플레이 루프, 의뢰·모험가·경제·시설·실패·엔딩의 연결 구조와 웹 프로토타입을 제안했다.
- 인간 피드백: 특정 게임 엔진을 고정하지 말고 웹 구현 가능성을 다시 비교하게 했으며, 초기에는 공개 배포보다 로컬 Git과 로컬 검증을 우선했다.

## 2. 승리 결과 UI와 한국어 UX

**표현 수준:** 비식별 재구성

> 과격하거나 기계적인 전투 문구를 자연스러운 한국어로 바꾸고, 승리 결과창을 단순 사각형 대신 세계관에 맞는 전투 보고서형 UI로 개선하라. 기존 행동의 의미는 보존하고 모바일 배치와 접근성을 확인하라. 여관의 길드원 제목에서는 불필요한 ‘패시브’ 표현을 제거하라.

- AI 활용: 금빛 테두리, 휘장, 보상 구획, 행동 버튼 위계를 구현하고 렌더링 회귀 테스트를 수정했다.
- 인간 피드백: 처치 수 단위를 더 자연스러운 생물 단위로 다시 고쳤고, 데스크톱·모바일 미리보기 확인 뒤 병합을 승인했다.

## 3. 구형 전술과 사용되지 않는 보상 제거

**표현 수준:** 비식별 재구성

> ‘파티 특수 전술 제거’가 어떤 UI, 전투 효과, 저장 데이터에 연결되는지 구현 전에 조사해 설명하라. 확인 후 구형 패널과 사용처가 없는 보스 증표를 제거하되 파티 편성과 최신 특수 연구는 보존하라. 기존 저장은 나머지 진행도를 정상 복원해야 한다.

- AI 활용: 세 가지 구형 전술, 증표의 보상·표시·소비, 관련 음향·스타일·저장 필드를 추적해 제거했다.
- 인간 피드백: 먼저 삭제 범위를 설명받은 뒤 패널과 증표 모두 제거하기로 결정했다. 범위 밖 승리 문구 수정은 원래 작업으로 되돌렸다.

## 4. 효과음 믹서와 청감 밸런스

**표현 수준:** 비식별 재구성

> 재화 획득음과 종료 팡파레가 BGM과 타격음에 묻히지만 전체 효과음 볼륨을 올리면 타격음이 과도해진다. 모든 효과음 경로가 같은 음량·음소거 설정을 따르는지 조사하고, 0% 완전 음소거와 여러 볼륨 단계가 일관되도록 연결한 뒤 개별 보정을 청감 테스트하라.

- AI 활용: 보상음의 개별 이득을 조정하고, 일부 무기 공격음이 전역 SFX 설정을 우회하는 경로를 찾아 15종 무기를 공통 설정에 연결했다.
- 인간 피드백: 일부 타격음만 설정을 무시한다는 원인 가설을 제시해 단순 증폭 작업을 전체 신호 경로 개선으로 확장했다.

## 5. 일반 전투 BGM 생성

**표현 수준:** 정확 문구 — AI가 사용자에게 제안한 영문 생성 프롬프트

> Moderately paced medieval fantasy battle music for a fantasy RPG, driving but restrained orchestral percussion, steady rhythmic string ostinatos, measured brass accents, adventurous and heroic melody, sustained combat tension without sounding frantic or like a final boss, instrumental only, no vocals or choir, approximately 110 BPM, clear game-ready mix, seamless loop with a natural transition between the ending and beginning

- 목적: 오래 반복해도 피로가 덜한 일반 전투곡 생성.
- 인간 피드백: 초기 시안이 너무 빠르다고 판단해 약 135 BPM 방향에서 약 110 BPM으로 낮추고, 최종 보스처럼 과장되지 않도록 했다.
- 결과: 후보 중 일반전 두 곡과 보스전 두 곡을 사람이 선택해 게임에 통합했다.

## 6. BGM 루프 구간 보정

**표현 수준:** 정확 문구 — AI가 사용자에게 제안한 영문 편집 프롬프트

> Replace the selected ending with a seamless loop transition that naturally leads back into the opening of the track. Preserve the same tempo, key, instrumentation, rhythm, energy, and mix. Do not create a finale, fade-out, cymbal tail, dramatic ending, pause, or sustained final chord. Finish cleanly on the exact bar boundary so the next beat connects naturally to the first beat of the song.

- 목적: 생성된 곡의 마지막 4~8마디를 첫 마디로 자연스럽게 되돌아가게 편집.
- AI 활용: Cover, Replace, Extend, Variation의 차이와 루프 편집 순서를 설명했다.
- 확인 한계: 이 문구가 실제 생성 서비스에서 최종 실행됐는지는 세션만으로 입증되지 않는다.

## 7. 생성된 네 곡의 장면별 순환

**표현 수준:** 비식별 재구성

> 일반 전투 후보 두 곡과 보스 전투 후보 두 곡을 모두 사용하라. 장면에 맞는 풀에서 선택하고 같은 전투 유형이 이어질 때 직전 곡을 피하라. 기존 음소거, 볼륨, 크로스페이드와 길드·필드 선택 BGM은 보존하라.

- AI 활용: 장면 변화 때만 풀의 커서를 진행하고, 두 오디오 플레이어 사이를 크로스페이드하는 로직과 테스트를 구현했다.
- 인간 피드백: 처음의 한 곡 선택 방침을 “있는 네 곡을 모두 돌려 쓰기”로 바꿨다.

## 8. 15종 무기 효과음 조사와 A/B 청취

**표현 수준:** 비식별 재구성

> 15종 무기의 무게, 속성, 공격 방식을 분석하고 각 무기에 필요한 스윙, 충돌, 저역, 마법 레이어를 추천하라. 상업 이용 가능한 공개 음원을 파일별로 조사하고, 기존안과 새 안을 무기별 행에서 직접 클릭 비교할 수 있는 오디션 화면을 만들어라. 실제 검격과 충돌을 주재료로 하고 마법은 보조로 사용하라.

Flow Music 실험용으로 다음과 같은 단발 효과음 프롬프트도 작성했다.

> 약 0.8초의 성휘 대검 단발 타격음을 만들어라. 무거운 칼바람, 갑옷 금속 충돌, 저역 몸통 충격, 약한 신성 폭발과 짧은 금속 잔향만 사용하고 음악, 박자, 보컬, 긴 잔향은 제외하라.

- AI 활용: 무기별 음향 특성표, 공개 후보와 라이선스 분류, 기존/후보 A/B 청취 도구를 만들었다.
- 인간 피드백: 합성 중심 첫 결과는 실제 재료가 부족하다고 평가했고, 연속 재생 대신 무기별 행 비교를 요구했다. 숨겨진 비교 패널도 직접 발견했다.
- 결과 상태: 개발자용 실험 브랜치까지만 만들었고 정식 게임에는 병합하지 않았다.

## 9. 장르가 전환되는 글리치 최종전

**표현 수준:** 비식별 재구성

> 마지막 스테이지 직후 기존 화면과 해상도를 유지한 채 글리치 보스 1페이즈를 클릭 공격으로 시작하고, 전체 UI가 붕괴한 뒤 2페이즈에서 길드 건물을 WASD로 조작하는 탄막전으로 전환하라. 자동 공격은 금지하고 기존 성장 중 길드 레벨만 제한적으로 반영하라. 빠른 단독 시험 모드, 모바일 입력, 동작 줄이기 대응을 제공하라.

- AI 활용: 1페이즈 클릭전, 화면 파쇄, 2페이즈 회피·코어 노출, 보스 파괴와 백색 전환을 엔진·렌더링·자산·테스트로 분리해 구현했다.
- 인간 피드백: 장착 검 커서, 공격 판정, 등장 시간, 자산 탄환의 크기·배경·회전·발사 위치를 반복 교정했다. 컷오프 직전에는 “한 발씩 생성하되 화면 동시 상한은 다섯 발”이라는 의미를 다시 명확히 했다.

## 10. 페이지 파쇄와 패배 물결 PoC

**표현 수준:** 비식별 재구성

> 게임 전체 UI가 조각나 사라지고 아래에 보스와 작은 실제 조작 건물만 드러나는 개념증명을 만들어라. 보스는 파쇄에서 제외하고 전환 전후 위치를 고정하라. 패배 시에는 설명 메시지 없이 화면을 물결로 완전히 덮고, 가려진 순간 길드 화면으로 교체한 뒤 역방향으로 드러내라.

- AI 활용: 삼각 파편 기반 페이지 전환과 세로 스트립 사인파 물결을 독립 PoC로 시험하고 최종전 작업에 인계했다.
- 인간 피드백: 거대한 길드 삽화가 아니라 실제 작은 플레이어 건물을 보여 달라고 정정하고, 보스 주변 배경과 해설 UI를 제거하게 했다.
- 결과 상태: 화면 파쇄는 제품화돼 main에 병합됐고, 패배 물결 후속안은 draft PR #138 범위다.

## 11. 독창적 글리치 적·보스 이미지

**표현 수준:** 비식별 재구성 — 생성 입력의 창작 조건만 보존

> 기존 프랜차이즈를 닮지 않는 독창적 글리치 적과 보스를 만들어라. 적은 찢어진 홀로그램·복셀 생물처럼, 보스는 폐허가 된 픽셀 성당의 왕관·분절된 팔·오류 코어를 가진 존재처럼 표현하라. 실루엣을 명확히 하고 읽을 수 있는 문구, HUD, 로고, 워터마크, 특정 작품과의 유사성은 제외하라.

후속 코드 기반 보스 외형 지시는 다음처럼 재구성했다.

> 다국어 문자, 숫자, 기호가 검은 원 내부에서 계속 변하는 글리프 구체를 만들고 청록·보라·분홍 확산광, 회전, RGB 분리, 가로 절단 글리치를 적용하라. 모든 조각은 원 밖으로 벗어나지 않게 하고 동작 줄이기 설정을 지원하라.

- AI 활용: 래스터 시안과 실시간 HTML·CSS·JavaScript 데모를 만들고, 코드 기반 글리프 구체를 실제 보스 외형으로 인계했다.
- 인간 피드백: 단어가 아니라 개별 글자, 영문 이외 문자, 완전한 원형 클리핑, 선명한 테두리 대신 부드러운 광, 더 강한 글리치를 요구했다.
- 결과 상태: 최종 보스는 특정 외부 캐릭터 이미지가 아니라 결정론적 코드 효과를 사용한다.

## 12. 공개 링크의 비로그인 접근 확인

**표현 수준:** 비식별 재구성

> 배포한 웹게임이 특정 AI 서비스 로그인을 요구하는지 확인하고, 누구나 로그인 없이 접속할 수 있는 공유 범위와 시크릿 창 검증 절차를 설명하라. 게임 자체 인증과 호스팅 서비스의 공유 설정은 구분하라.

- AI 활용: 공개 범위 선택, 게임의 로그인 강제 여부 확인, 비로그인 브라우저 시험 절차를 안내했다.
- 확인 한계: 세션에는 최종 공개 URL을 비로그인 상태로 검증한 결과가 없다.

## 제출 전에 보강해야 할 프롬프트 정보

- 최초 음악 생성 때 실제 입력한 정확 문장, 모델 세부 버전, seed, 생성 파라미터와 리믹스 설정값은 기록되지 않았다.
- 루프 보정 프롬프트의 실제 실행 여부와 Flow Music 효과음 시안의 채택 여부가 확인되지 않는다.
- 생성된 네 BGM의 곡별 프롬프트·모델·생성 시각·편집 이력이 파일 단위로 연결돼 있지 않다.
- ImageGen의 정확한 모델 버전·seed와 각 출력 파일의 생성 작업 ID는 보존되지 않았다.
- 공개 효과음 후보는 최종 채택 파일을 기준으로 원본 페이지, 제작자, 라이선스 스냅샷을 다시 대조해야 한다.
- draft PR #138의 후속 피날레 요구는 완료 기능과 구분하고, 병합 뒤 프롬프트-구현 대응표를 갱신해야 한다.
