# desk64 Clicker Guild AI 활용 내역 요약

## 한눈에 보는 범위

2026년 8월 9일부터 10일까지 `desk64`에서 진행된 Clicker Guild 관련 사용자 세션 11개를 컷오프 시점 기준으로 요약했다. 실질 사용자 요청은 115개였고, assistant가 사용자에게 보여 준 진행·결과 메시지는 439개였다. 저장 과정에서 생긴 포크·보조 에이전트·압축 이력은 하나의 논리 세션으로 묶었으며 원문은 싣지 않았다.

이 기록에서 AI는 단순 코드 생성뿐 아니라 요구사항 분해, 웹·라이선스 조사, UI·오디오·게임 엔진 구현, 테스트와 빌드, 브라우저 화면·청감 검증, GitHub Issue·PR 조율, 다른 세션으로의 설계 인계를 담당했다. 사용자는 창작 방향, 체감 품질, 용어와 조작 의미, 병합 승인, 라이선스 선택을 결정했고 결과를 직접 확인하면서 반복적으로 수정 방향을 제시했다.

제출 PDF 작성자는 다음 세부 문서를 함께 사용해야 한다.

- `technical-notes.md`: 런타임과 개발 단계 AI의 구분, 앱·오디오·피날레 구조, 개발·검증 절차
- `prompt-catalog.md`: 주요 프롬프트와 공통 지시, 인간 피드백, 정확 문구와 재구성의 구분
- `external-sources.md`: 외부 에셋·AI 생성물·오픈소스 출처와 미확인 항목

## AI 도구·활용 방식

### 1. 개발과 검증

Codex가 저장소 구조와 기존 구현을 분석하고, 작업별 독립 worktree에서 코드를 수정했다. 변경 뒤에는 범위에 맞춰 lint, production build, 단위·렌더링·회귀 테스트를 실행했다. UI와 인터랙션은 전용 로컬 서버에서 데스크톱·모바일 화면을 직접 조작해 확인했고, 오디오 작업은 음소거·볼륨 단계·장면 전환·파일 로드를 함께 검증했다.

### 2. 조사와 창작 보조

전투 BGM에서는 사용자가 로그인한 AI 음악 서비스의 프롬프트 작성과 옵션 선택을 보조하고, 선정된 네 곡을 게임에 통합했다. 무기 효과음에서는 생성형 서비스, 제작 자료, 공개 게임 오디오 커뮤니티와 라이선스를 조사하고 15종 비교 청취 실험을 구성했다. 글리치 피날레에서는 시각 사례 조사와 실시간 HTML·CSS·JavaScript 프로토타입을 통해 정적 설명보다 빠르게 연출을 비교했다.

### 3. 병렬 에이전트와 협업 관리

규모가 큰 피날레 작업은 엔진, 시각 효과, 테스트, 브라우저 QA처럼 수정 경로가 다른 하위 작업으로 나누었다. GitHub Issue를 작업·소유권 기록으로, PR을 코드·검증 기록으로 사용했고, 완료된 PoC는 관련 세션에 요구사항과 검증 조건을 함께 인계했다. 사용자 승인 전에는 병합하지 않고, PR별 확인 서버를 사용한 뒤 병합 후 종료하는 절차도 AI가 조율했다.

## 대표적인 인간-AI 반복 패턴

- 사용자가 “화면에 동시에 다섯 개”라는 의도를 설명하자 AI가 처음의 묶음 생성 해석이 잘못됐음을 인정하고 순차 생성·동시 상한으로 수정 방향을 다시 잡았다.
- 사용자가 개발자 화면에 무기 선택 UI가 보이지 않는다고 지적하자 AI가 처음의 레이아웃 추정을 철회하고 CSS 숨김 규칙을 찾아 전용 UI를 복구했다.
- 사용자가 일부 타격음만 볼륨 설정을 무시한다고 추정하자 AI가 오디오 그래프를 추적해 설정 우회 경로를 찾아냈고, 단순 증폭에서 전체 설정 일관성 개선으로 작업을 확장했다.
- 사용자가 화면 파쇄를 공격 기법이 아닌 자기 게임의 연출로 한정하자 AI가 취약점 재현 대신 저장소가 소유한 시각 PoC로 안전하게 전환했다.
- 주관적인 음악·화면 품질은 사용자가 직접 듣고 본 뒤 승인했고, AI는 그 전후의 구현·검증·병합 절차를 담당했다.

## NHN2026 기술문서용 서술 초안

Clicker Guild 개발에서는 Codex를 요구사항 분석부터 구현, 검증, 협업 기록까지 이어지는 개발 보조 도구로 활용했다. 사용자가 게임의 창작 방향과 체감 품질을 결정하면 AI가 이를 독립 작업으로 분해하고 기존 코드와 충돌 범위를 조사한 뒤 기능을 구현했다. 변경은 자동 테스트와 production build를 거쳤으며, UI·전투·오디오는 전용 로컬 서버에서 실제 화면과 소리를 확인한 후에만 병합했다.

AI 활용은 코드 작성에 한정되지 않았다. 전투 BGM용 생성 프롬프트 작성, 공개 효과음과 라이선스 조사, 무기 15종 비교 청취 도구 제작, 글리치 보스와 화면 붕괴 연출의 인터랙티브 프로토타이핑에도 사용했다. 특히 피날레 작업에서는 다중 에이전트를 엔진·연출·테스트·QA로 분리하고 GitHub Issue와 PR을 통해 수정 경로와 검증 결과를 공유했다.

최종 결정은 사람이 맡았다. 사용자는 AI 결과를 직접 실행해 보면서 용어, 조작 방식, 탄환 수의 의미, 충돌 범위, 음악의 반복감처럼 자동 테스트만으로 판단하기 어려운 부분을 교정했다. AI는 잘못 해석한 요구를 수정하고 회귀 검증을 반복했으며, 사용자가 승인한 결과만 병합했다. 이 과정은 AI를 자율 대체자가 아니라 빠른 탐색·구현·검증을 담당하는 협업 도구로 사용한 사례다.

## 제한사항

이 문서는 대화 원문 증빙이 아니라 개인정보를 제거한 의미 요약이다. 삭제됐거나 다른 PC에만 있는 세션은 포함하지 않으며, 컷오프 뒤에 이어진 활성 작업도 반영하지 않는다.

기술 구조와 AI 활용 과정은 현재 자료로 초안을 만들 수 있지만 제출 패키지는 아직 완결되지 않았다. 특히 Flow Music 네 곡의 생성 당시 약관·생성 대장, ImageGen 파일별 모델·프롬프트·생성 기록, 다수 이미지의 출처·권리 선언, Vivid Motion 약관 사본, production 의존성 OSS 고지가 부족하다. draft PR #138의 기능도 병합 완료 기능처럼 서술하면 안 된다. 최종 PDF에서는 `external-sources.md`의 상태 표와 보완 목록을 반드시 반영해야 한다.
