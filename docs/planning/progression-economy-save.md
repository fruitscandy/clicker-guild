# 성장·경제·저장 시스템 MVP

## 1. 목적과 범위

이 문서는 전투 그래픽·스킬 구현과 독립적으로 붙일 수 있는 성장, 경제, 스테이지 진행, 오프라인 보상, 저장 규칙을 정의한다. 현재 기획의 `최대 4인 편성`, `F → E → D → C → B → A → S` 길드원 25명, `10지역 × 10스테이지` 구조를 전제로 한다.

첫 플레이 빌드의 목표는 **1지역 초보자의 숲(1-1~1-10)을 처음부터 보스 처치까지 진행하고, 종료 후 다시 실행해도 성장이 유지되는 것**이다. 수치는 서버 권위형 라이브 서비스가 아니라 로컬 싱글 플레이 프로토타입 기준이다.

### MVP(P0)

- 골드 1종, 길드원 경험치 1종
- 길드원 레벨과 골드 강화
- 고정 순서 영입(가챠 없음)
- 1지역 10스테이지 해금과 재도전
- 최대 4인 편성 저장
- 오프라인 골드 보상
- 버전이 있는 로컬 저장, 백업, 마이그레이션

### MVP 이후(P1/P2)

- P1: 2~10지역 수치 튜닝, E등급 이상 영입, 업적, 간단한 일일 보상
- P2: 가챠, 중복 조각, 장비, 승급 재료, 환생, 다중 재화, 광고/결제, 서버 동기화

P2 항목은 첫 빌드에 넣지 않는다. 특히 가챠와 환생은 경제 전체를 다시 설계하게 하므로 현재 저장 스키마에도 확정 필드로 만들지 않는다.

## 2. 핵심 플레이 루프

1. 현재 스테이지의 몬스터를 클릭 공격과 편성 길드원의 자동 공격으로 처치한다.
2. 처치 즉시 골드와 참전 길드원 경험치를 받는다.
3. 일반 스테이지는 같은 몬스터 10마리, 보스 스테이지는 보스 1마리를 처치하면 최초 클리어된다.
4. 골드로 길드원을 강화하고, 경험치로 길드원 레벨이 자동 상승한다.
5. 특정 스테이지 최초 클리어 시 영입 후보가 해금된다. 골드를 내고 확정 영입한다.
6. 새 길드원을 최대 4인 파티에 편성하고 다음 스테이지에 도전한다.
7. 앱을 종료했다 돌아오면 마지막 저장 이후 최대 8시간에 대한 골드 일부를 받는다.

실패 패널티는 없다. 전투에서 전멸하거나 보스를 제한 시간 안에 잡지 못하면 같은 스테이지를 즉시 재도전하거나 이전 스테이지로 돌아가 골드와 경험치를 모을 수 있다.

## 3. 공통 식별자와 진행 인덱스

- 스테이지 ID: `1-1`부터 `10-10`까지 문자열로 표현한다.
- 전체 순번 `n`: `n = (지역 - 1) × 10 + 스테이지` (`1-1`은 1, `1-10`은 10, `10-10`은 100)
- 길드원 ID: 표시 이름과 분리된 영문 소문자 ID를 쓴다. 예: `roan`, `mia`, `finn`.
- 밸런스 계산은 ID나 표시 이름이 아니라 `n`, 등급, 성장 레벨만 사용한다.

## 4. 성장·경제 규칙

### 4.1 골드

골드는 몬스터 처치, 최초 클리어 보너스, 오프라인 보상으로 얻고 강화와 영입에 사용한다. MVP에서 골드 외 유료·희귀 재화는 없다.

몬스터 1마리의 기본 골드:

```text
normalGold(n) = round(8 × 1.15^(n - 1))
bossGold(n)   = normalGold(n) × 3
firstClearBonus(n) = normalGold(n) × (일반 5, 보스 15)
```

최초 클리어 보너스는 스테이지당 한 번만 지급하며 `firstClearClaimed`로 기록한다. 재도전에서는 처치 골드만 받는다.

### 4.2 길드원 경험치와 레벨

전투에 편성된 길드원은 전투 종료 시 각자 동일한 경험치를 받는다. 인원수로 나누지 않아 4인 편성을 손해 보지 않게 한다. 미편성 길드원은 경험치를 받지 않는다.

```text
normalXp(n) = round(4 × 1.10^(n - 1))
bossXp(n)   = normalXp(n) × 5
nextLevelXp(level) = round(10 × level^1.35)
```

- 시작 레벨: 1
- MVP 최대 레벨: 20
- 필요 경험치는 현재 레벨에서 다음 레벨까지의 값이며, 초과 경험치는 이월한다.
- 한 번의 보상으로 여러 레벨이 오르면 조건을 만족하는 동안 반복해서 레벨업한다.
- 레벨 1 증가당 기본 공격 관련 수치가 5% 증가한다.

### 4.3 골드 강화

강화는 경험치 레벨과 별개의, 플레이어가 골드를 쓰는 성장 축이다. 실패·확률·하락은 없다.

```text
enhanceCost(등급, e) = round(gradeBaseCost × 1.55^e)
```

여기서 `e`는 현재 강화 수치이며, +0에서 +1 비용은 등급 기본 비용이다.

| 등급 | 기본 비용 | 공격 배율 기준 |
|---|---:|---:|
| F | 20 | 1.00 |
| E | 50 | 1.35 |
| D | 120 | 1.80 |
| C | 300 | 2.45 |
| B | 750 | 3.30 |
| A | 1,800 | 4.50 |
| S | 5,000 | 6.20 |

- MVP 강화 상한: +10
- 강화 1회당 공격 관련 수치가 10% 증가한다.
- 비용을 먼저 검증한 뒤 한 트랜잭션에서 골드 차감과 강화 증가를 함께 처리한다.
- 공격력 최종 성장 배율:

```text
growthMultiplier = gradeMultiplier
                 × (1 + 0.05 × (level - 1))
                 × (1 + 0.10 × enhancement)
```

스킬의 계수·쿨다운 자체는 전투 시스템 소유다. 성장 시스템은 최종 능력치 계산에 사용할 `growthMultiplier`만 제공한다.

### 4.4 영입

MVP에서는 확정 영입만 사용한다. 해금 조건을 만족하면 후보가 보이고, 한 번 골드를 내면 영구 소유한다. 이미 소유한 길드원은 다시 구매할 수 없다.

| 해금 조건 | 길드원 | 등급 | 영입 비용 |
|---|---|:---:|---:|
| 새 게임 시작 | 견습 전사 로안 | F | 무료/자동 |
| 1-2 최초 클리어 | 떠돌이 궁수 미아 | F | 60 |
| 1-4 최초 클리어 | 골목 도적 핀 | F | 100 |
| 1-6 최초 클리어 | 수습 마법사 루루 | F | 160 |
| 1-8 최초 클리어 | 신입 사제 엘리 | F | 240 |
| 1-10 최초 클리어 | 방패병 가론 | E | 400 |

영입 후보의 해금과 실제 소유를 구분한다. 1지역 밖의 19명은 데이터에 정의할 수 있지만 MVP UI에는 노출하지 않는다.

### 4.5 파티 편성

- 1~4명, 같은 길드원 중복 편성 불가
- 새 게임은 로안 1명으로 시작
- 영입 직후 자동 편성하지 않는다. 빈 슬롯이 있으면 UI에서 “편성”을 권장한다.
- 전투 중 편성 변경은 다음 몬스터부터 적용한다. 저장에는 길드원 ID 배열만 기록한다.

## 5. 스테이지 해금과 반복

- 새 게임에서 `1-1`만 해금한다.
- 현재 스테이지 최초 클리어 시 다음 스테이지를 해금한다.
- 일반 스테이지: 해당 몬스터 10마리 처치
- 10번째 스테이지: 보스 1마리 처치, 권장 제한 시간 30초
- 이미 해금한 스테이지는 자유롭게 재도전할 수 있다.
- 보스 실패 시 보스 HP는 초기화되고 획득한 피해량은 저장하지 않는다.
- 스테이지 도중 앱이 종료되면 현재 몬스터 HP와 일반 처치 횟수는 저장하지 않는다. 재실행 시 선택 스테이지의 첫 몬스터부터 시작한다.

`highestClearedStage`는 파생 가능한 값이지만 빠른 조회와 마이그레이션을 위해 저장한다. 실제 해금 판정은 `clearedStages`를 우선하며, 둘이 다르면 `clearedStages`에서 다시 계산한다.

## 6. 초기 밸런스 공식과 예시

### 6.1 몬스터 체력

```text
normalHp(n) = round(30 × 1.18^(n - 1))
bossHp(n)   = normalHp(n) × 5
```

전투 시스템은 이 체력을 사용하되, 방어력·속성 저항·회피는 MVP에서 넣지 않는다. 보스 제한 시간만으로 성장 벽을 만든다.

### 6.2 1지역 예시 값

| 스테이지 | 종류 | HP/마리 | 골드/마리 | XP/참전 길드원 | 최초 클리어 보너스 |
|---|---|---:|---:|---:|---:|
| 1-1 | 일반 | 30 | 8 | 4 | 40골드 |
| 1-2 | 일반 | 35 | 9 | 4 | 45골드 |
| 1-5 | 일반 | 58 | 14 | 6 | 70골드 |
| 1-9 | 일반 | 113 | 24 | 9 | 120골드 |
| 1-10 | 보스 | 665 | 84 | 45 | 420골드 |

반올림 구현에 따라 1 정도 차이 날 수 있으므로 테스트에서는 같은 공용 계산 함수를 사용한다. 표를 하드코딩하지 않는다.

### 6.3 초반 체감 목표

- 1-1 첫 처치: 3~6초
- 1-1 최초 클리어: 1분 이내
- 첫 강화: 1-1 클리어 전후
- 미아 영입: 1-3 진입 전후
- 1-10 보스 도달: 신규 플레이 20~40분
- 보스 첫 도전은 준비 없이 실패할 수 있으나, 5~10분 강화 후 승리 가능

수치 검증은 `예상 파티 DPS`, `몬스터 HP / DPS`, `분당 골드`, `다음 강화까지 걸리는 시간` 네 지표로 한다. 실제 전투 계수가 정해지면 HP와 보상 성장률을 유지한 채 기준값 30과 8부터 조정한다.

## 7. 오프라인 보상 최소안

오프라인에서는 스테이지 클리어, 경험치, 영입 해금이 일어나지 않고 골드만 지급한다.

```text
elapsedSeconds = clamp(now - lastSeenAt, 0, 8시간)
offlineGold = floor(elapsedSeconds × offlineGoldPerSecond × 0.5)
```

- `offlineGoldPerSecond`는 종료 직전 최근 60초간 실제 처치로 얻은 골드/초의 지수 이동 평균(EMA)이다.
- 보스전·최초 클리어 보너스·수동 지급은 표본에서 제외한다.
- 유효한 처치 표본이 없으면 0으로 저장한다.
- 저장 가능한 최대 속도는 `normalGold(최고 클리어 일반 스테이지 n) / 1초`, 즉 초당 1킬에 해당하는 상한을 넘지 못하게 한다.
- 최소 인정 시간은 60초, 최대 누적 시간은 8시간, 효율은 50%다.
- 보상은 재실행 후 요약 팝업에서 한 번만 수령하고 즉시 저장한다.

빠른 MVP에서는 `수령 버튼을 눌러야 지급` 방식으로 구현한다. 팝업을 닫으면 같은 세션에서 다시 열 수 있게 하되, 지급 완료 후에는 재지급할 수 없다.

## 8. 저장 데이터 스키마 초안

JSON 예시:

```json
{
  "schemaVersion": 1,
  "saveId": "local-uuid",
  "createdAt": 1786200000000,
  "updatedAt": 1786203600000,
  "economy": {
    "gold": 315,
    "lifetimeGoldEarned": 940,
    "lifetimeGoldSpent": 625
  },
  "progression": {
    "selectedStage": "1-6",
    "highestClearedStage": "1-5",
    "clearedStages": ["1-1", "1-2", "1-3", "1-4", "1-5"],
    "firstClearClaimed": ["1-1", "1-2", "1-3", "1-4", "1-5"]
  },
  "members": {
    "roan": { "owned": true, "unlocked": true, "level": 5, "xp": 7, "enhancement": 3 },
    "mia":  { "owned": true, "unlocked": true, "level": 3, "xp": 2, "enhancement": 1 },
    "finn": { "owned": false, "unlocked": true, "level": 1, "xp": 0, "enhancement": 0 }
  },
  "party": ["roan", "mia"],
  "offline": {
    "lastSeenAt": 1786203600000,
    "goldPerSecond": 0.45,
    "pendingGold": 0,
    "pendingCalculatedAt": null
  },
  "settings": {
    "musicVolume": 0.8,
    "sfxVolume": 0.8,
    "locale": "ko-KR"
  },
  "stats": {
    "monstersDefeated": 54,
    "bossesDefeated": 0,
    "manualClicks": 231
  }
}
```

### 저장 원칙

- 자동 저장: 스테이지 클리어, 영입, 강화, 편성 변경, 오프라인 보상 수령 직후
- 주기 저장: 플레이 중 30초마다(변경이 있을 때만)
- 주기 저장과 앱 백그라운드 전환 시 `offline.lastSeenAt`도 현재 시각으로 갱신한다.
- 종료 이벤트 저장은 보조 수단으로만 사용한다. 모바일/브라우저 종료 이벤트는 보장되지 않는다.
- 전투 중 HP, 애니메이션 프레임, 쿨다운은 저장하지 않는다.
- 모든 수치 입력은 로드 시 유한 숫자인지 검사하고 허용 범위로 보정한다.
- 주 저장과 직전 정상 저장 백업 1개를 유지한다. 주 저장 파싱/검증 실패 시 백업을 불러온다.
- 저장 직렬화 결과에 체크섬을 붙일 수 있으면 붙이되, 로컬 체크섬은 보안 장치가 아니라 손상 탐지 장치다.

### 새 게임 기본값

- 골드 0
- `1-1` 선택, 클리어 목록 없음
- 로안 소유/해금, 레벨 1, XP 0, 강화 +0
- 파티 `['roan']`
- 나머지 길드원 미소유, 스테이지 조건에 따라 해금

## 9. 버전 마이그레이션

1. 저장 로드 전에 원본 문자열을 백업한다.
2. JSON 파싱과 최소 필드 검증을 한다.
3. `schemaVersion`이 없으면 0으로 본다.
4. 현재 버전보다 낮으면 `v0 → v1 → v2`처럼 한 단계씩 순서대로 순수 함수 마이그레이션을 적용한다.
5. 각 단계 후 필수 필드와 범위를 다시 검증한다.
6. 성공한 경우에만 현재 버전으로 저장하고 백업을 갱신한다.
7. 현재 코드보다 높은 버전이면 덮어쓰지 말고 “더 최신 버전에서 생성된 저장” 오류를 표시한다.
8. 마이그레이션 실패 시 원본과 백업을 보존한 채 새 게임/백업 복구 선택지를 제공한다.

마이그레이션 함수 예시 계약:

```text
migrateV0ToV1(oldSave) -> newSave
validateV1(save) -> { valid, errors, sanitizedSave }
```

저장 필드를 제거하기보다 새 기본값을 추가하는 방향을 우선한다. 길드원 및 스테이지 정적 데이터는 저장에 복제하지 않고 코드/데이터 테이블에서 읽어 밸런스 패치가 가능하게 한다.

## 10. 악용·손상 방지 최소안

로컬 싱글 플레이 MVP에서 완전한 치트 방지는 목표가 아니다. 중복 지급, 음수 재화, 시계 조작으로 인한 큰 보상만 막는다.

- 골드 차감은 `보유량 >= 비용` 검증 후 단일 트랜잭션으로 처리한다.
- 영입·강화 버튼은 요청 중 비활성화하고, 처리 함수에서도 상태를 다시 검증한다.
- 골드, XP, 레벨, 강화는 음수·NaN·Infinity를 허용하지 않는다.
- 레벨은 1~20, 강화는 0~10, 파티는 소유한 고유 ID 최대 4개로 보정한다.
- 오프라인 경과 시간이 음수면 0, 8시간을 넘으면 8시간으로 제한한다.
- 기기 시간이 과거로 이동하면 오프라인 보상을 0으로 하고 `lastSeenAt`을 무조건 과거 값으로 되돌리지 않는다.
- 복귀 시 보상을 계산하면 먼저 `pendingGold`와 `pendingCalculatedAt`을 저장하고 `lastSeenAt`을 현재 시각으로 옮긴 뒤 팝업을 연다. 수령 시 `pendingGold`를 골드에 더하고 0으로 만드는 작업을 한 트랜잭션으로 처리한다.
- 최초 클리어 보너스와 영입은 ID 기반 집합으로 중복 여부를 검사한다.
- 저장 로드 후 `lifetimeGoldEarned - lifetimeGoldSpent`와 현재 골드가 심하게 어긋나면 로그만 남기고, MVP에서는 플레이를 차단하지 않는다.

서버가 없는 이상 사용자가 파일 자체를 편집하는 것은 막을 수 없다. 경쟁 순위나 결제가 추가될 때 서버 기준 시간·재화 원장·서명된 저장으로 별도 전환한다.

## 11. 구현 경계

성장 시스템이 제공할 인터페이스:

- `getStageBalance(stageId)` → HP, 처치 골드, XP, 최초 보너스, 보스 여부
- `grantKillRewards(stageId, activeMemberIds)` → 골드/XP 반영 결과
- `claimFirstClear(stageId)` → 다음 스테이지/영입 후보 해금 결과
- `enhanceMember(memberId)` → 비용 검증과 결과
- `recruitMember(memberId)` → 조건/비용 검증과 결과
- `setParty(memberIds)` → 검증된 편성 결과
- `calculateGrowthMultiplier(memberId)` → 전투 시스템 전달 값
- `createOfflineReward(now)` / `claimOfflineReward()`
- `saveGame()` / `loadGame()` / `migrateSave()`

전투 시스템은 “누가 처치했고 어떤 스킬이 발동했는지”를 성장 시스템에 넘기지 않아도 된다. 스테이지 ID와 전투 종료 시점의 편성 ID만 전달하면 된다. 그래픽 시스템은 저장 데이터에 직접 접근하지 않고 이벤트 결과를 표시한다.

## 12. 구현 티켓과 완료 조건

### P0-1 정적 데이터와 밸런스 계산기

작업:

- 스테이지 ID 변환, 보스 판정, HP/골드/XP/최초 보너스 계산
- 등급별 비용·배율과 1지역 영입 테이블 정의

완료 조건:

- `1-1`, `1-10`, `10-10`의 인덱스와 보스 판정 단위 테스트 통과
- 문서의 1지역 예시 값과 계산 결과 일치
- UI와 전투 코드가 숫자를 중복 하드코딩하지 않음

### P0-2 경제 트랜잭션

작업:

- 골드 획득/차감, 강화, 영입, 최초 클리어 보너스 처리

완료 조건:

- 골드 부족 시 상태가 전혀 바뀌지 않음
- 빠르게 버튼을 연속 입력해도 강화·영입이 중복 처리되지 않음
- 모든 변경 결과가 저장 요청을 발생시킴

### P0-3 길드원 경험치와 편성

작업:

- 참전 길드원 XP 지급, 연속 레벨업, 성장 배율, 파티 검증

완료 조건:

- 1명과 4명 편성 모두 각 참전자가 표의 XP 전액을 받음
- 최대 레벨에서 XP가 넘쳐도 레벨 20을 초과하지 않음
- 미소유·중복 ID 또는 5명 편성이 저장되지 않음

### P0-4 스테이지 진행

작업:

- 일반 10킬/보스 1킬 클리어, 다음 스테이지 해금, 재도전

완료 조건:

- 새 게임에서 1-1 외 스테이지 진입 불가
- 최초 클리어 보너스와 다음 스테이지 해금이 정확히 한 번 발생
- 앱 재실행 후 클리어/해금 상태 유지
- 1-10 처치 후 1지역 완료 상태 표시

### P0-5 저장·복구·마이그레이션

작업:

- v1 저장 스키마, 자동 저장, 백업, 검증, v0 테스트 픽스처 마이그레이션

완료 조건:

- 강화/영입/편성/클리어 후 강제 종료를 모사해도 마지막 확정 행동 유지
- 손상된 주 저장에서 정상 백업 복구
- 없는 필드, 잘못된 숫자, 중복 파티 ID를 안전한 값으로 보정
- 미래 버전 저장을 자동으로 덮어쓰지 않음

### P0-6 오프라인 보상

작업:

- 최근 60초 처치 골드 속도 측정, 종료 시 저장, 복귀 시 계산과 1회 수령

완료 조건:

- 59초 이하는 0, 60초 이상은 공식대로 지급
- 8시간을 초과해도 8시간분만 지급
- 기기 시간이 과거면 0 지급
- 팝업을 반복 열거나 앱을 즉시 재실행해도 같은 보상이 두 번 지급되지 않음

### P0-7 통합 플레이테스트와 수치 조정

작업:

- 새 저장으로 1-1부터 1-10까지 플레이하고 시간/막힘 기록

완료 조건:

- 1-1 첫 처치와 1지역 완료가 목표 시간 범위에 들어옴
- 최소 2명 이상 영입하고 강화가 3회 이상 유의미하게 발생
- 3분 이상 아무 구매도 못 하는 구간이 반복되면 비용 또는 보상을 조정
- 수정한 기준값과 이유를 밸런스 데이터 변경 기록에 남김

### P1/P2 백로그

- P1: 나머지 지역의 권장 전투력과 영입 해금표 확정
- P1: 자동 진행, 일괄 강화, 오프라인 보상 상세 내역
- P1: 저장 내보내기/가져오기와 사용자 확인 UI
- P2: 장비, 승급, 중복 영입, 환생, 일일/주간 콘텐츠
- P2: 서버 저장, 계정 연동, 경쟁·결제용 재화 원장

## 13. 출시 전 최소 체크리스트

- 새 게임 → 로안 전투 → 강화 → 미아 해금/영입 → 2인 편성 → 1-10 보스 처치가 끊김 없이 가능하다.
- 골드가 음수가 되거나 최초 보상이 중복 지급되는 경로가 없다.
- 저장 삭제 없이 앱을 3회 재실행해도 골드, 길드원, 편성, 클리어가 동일하다.
- 주 저장을 일부 손상시켰을 때 백업 복구 또는 안전한 새 게임 선택이 가능하다.
- 1분, 1시간, 8시간, 24시간 시계 차이에 대한 오프라인 보상이 정의대로 제한된다.
- 전투/스킬 수치를 바꿔도 성장 문서의 공용 계산기와 데이터 테이블만 조정하면 된다.
