# Clicker Guild 병렬 실행 보드

> 기준일: 2026-08-09
> 목표: 전투 그래픽·스킬 레인과 충돌하지 않으면서 1지역 MVP의 비전투 기반을 준비한다.

## 현재 레인

| 레인 | 담당 | 상태 | 소유 범위 |
|---|---|---|---|
| 전투 그래픽·스킬 | 다른 PC | 진행 중 | 전투 화면, 전투 에셋, 스킬 로직·연출 |
| MVP 공백 감사 | 이 PC / 세션 A | 완료 | `docs/planning/mvp-gap-audit.md` |
| 성장·경제·저장 | 이 PC / 세션 B | 완료 | `docs/planning/progression-economy-save.md` |
| 기술·통합 청사진 | 이 PC / 세션 C | 진행 중 | `docs/planning/implementation-integration-blueprint.md` |
| 최종 통합·우선순위 | 이 PC / 메인 | 진행 중 | 이 보드, 협업 규칙, 인계 검수 |

## 가장 중요한 차단 요소

현재 `main`에는 실행 가능한 게임 프로젝트가 없다. 패키지 설정, 런타임 코드, 테스트와 빌드 설정도 없다. 따라서 다음 중 어느 쪽인지 확인하기 전에는 별도 프레임워크를 생성하지 않는다.

1. 다른 PC가 전투 작업과 함께 프로젝트 골격도 만들고 있다.
2. 다른 PC는 그래픽·스킬 자료만 만들고 있고 프로젝트 골격은 아직 없다.

두 PC가 서로 다른 프레임워크로 골격을 만들면 병합 비용이 가장 크게 발생한다.

## 전투 PC에서 받아야 할 최소 인계 정보

- 브랜치 이름과 기준 커밋
- 사용 중인 기술 스택과 정확한 실행 명령
- 생성·수정한 파일 경로
- 전투 진입 시 필요한 입력 데이터
- 전투 종료 시 반환 가능한 결과 데이터
- 스킬 ID와 길드원 ID 규칙
- 런타임 에셋 경로, 크기, 기준점, 방향
- 미완성 항목과 알려진 문제

권장 책임 경계:

- 전투 레인은 `battleId`, 승패/중단, 처치 수, 소요 시간 등 결과 근거를 반환한다.
- 진행 레인은 보상, 최초 클리어, 다음 스테이지 해금을 한 번만 확정한다.
- 같은 `battleId`의 결과가 반복 전달돼도 보상은 중복 지급하지 않는다.

## P0 실행 순서

### Gate 0 — 프로젝트 골격 소유자 확정

- [ ] 다른 PC의 브랜치·파일·스택 확인
- [ ] 웹 MVP 기준 실행 환경 확정
- [ ] 루트 설정과 공용 데이터 계약의 단일 통합 담당 지정
- [ ] 1지역 1-1~1-10, 최대 4인, 골드 1종으로 MVP 범위 잠금

완료 조건: 두 PC가 같은 실행 명령과 폴더 구조를 기준으로 작업한다.

### Gate 1 — 공용 데이터와 저장 기반

- [ ] 길드원, 몬스터, 스테이지 ID 규칙 고정
- [ ] 정적 콘텐츠 스키마와 로드 검증 구현
- [ ] 성장·경제 계산기를 순수 함수로 구현
- [ ] 저장 v1, 자동 저장, 백업과 손상 복구 구현
- [ ] 저장 마이그레이션 테스트 작성

소유 예약: `src/domain/**`, `src/content/**`, `src/services/save/**`, `tests/save/**`

### Gate 2 — 비전투 사용자 흐름

- [ ] 시작/이어하기
- [ ] 로비
- [ ] 길드원 목록·상세·강화
- [ ] 최대 4인 편성
- [ ] 1-1~1-10 스테이지 선택과 잠금 상태
- [ ] 설정과 데이터 초기화

소유 예약: `src/ui/shell/**`, `src/features/guild/**`, `src/features/stage/**`, `src/features/settings/**`

### Gate 3 — 전투 연결

- [ ] 실제 전투 없이 성공·패배·중단을 돌려주는 가짜 전투 어댑터
- [ ] 전투 입력·결과 계약 검증
- [ ] 결과 1회 처리와 보상 중복 방지
- [ ] 실제 전투 모듈로 교체해 전체 흐름 확인

소유 예약: `src/integration/combat/**`, `tests/integration/combat-contract/**`

### Gate 4 — 첫 빌드 검증

- [ ] 새 게임 → 로안 편성 → 1-1 진입
- [ ] 승리 → 보상 → 1-2 해금
- [ ] 강화 → 변경된 성장 배율이 다음 전투 입력에 포함
- [ ] 종료·재실행 → 재화, 편성, 강화, 진행 복원
- [ ] 같은 전투 결과 재처리 → 보상 증가 없음
- [ ] 1-10 보스까지 20~40분 목표로 플레이테스트

## 지금부터 금지할 작업

- 프로젝트 골격을 확인하기 전 두 번째 프레임워크 생성
- 2지역 이후 실제 콘텐츠 구현
- 확률형 모집, 장비, 환생, 다중 재화 추가
- 25명 전원의 애니메이션 완성 대기
- 진행 시스템과 전투 시스템 양쪽에서 보상 지급
- 기존 `docs/experimental-asset/**` 원본 덮어쓰기

## 통합 주기

1. 각 작업은 독립 브랜치/worktree와 독립 파일 소유 범위를 사용한다.
2. 결과가 완료되면 브랜치, 기준 커밋, 실행·검증 결과를 보고한다.
3. 통합 담당은 공용 계약을 먼저 병합하고 기능 브랜치를 작은 단위로 가져온다.
4. 1~2시간마다 최소 실행 빌드를 확인한다.
5. `main`에는 실행 불가능한 중간 상태를 넣지 않는다.
